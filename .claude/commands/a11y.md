# /a11y

`a11y-auditor` 를 호출하여 접근성 점검을 수행한다.

## 인자

- `/a11y` — 허브 + 최근 변경 도구
- `/a11y pdf-merge` — 단일 도구

## 절차

1. **정적 검사**
   ```bash
   cd web && npx axe-cli http://localhost:3000/tools/{slug} 2>/dev/null || echo "axe 미설치"
   ```
   `@axe-core/cli` 미설치 시 페이지 코드 정적 분석으로 폴백.

2. **수동 시뮬레이션** — 페이지 코드를 읽고 다음 검사:
   - `<button>` 또는 `role="button"` 있는 클릭 요소
   - `aria-label` 누락된 아이콘 버튼
   - `role="progressbar"` + `aria-valuenow/min/max`
   - 색 대비 위반 (`text-muted-foreground` 다크모드)
   - `<label>` 또는 `aria-labelledby` 누락 폼
   - `tabIndex` 부정사용 (`-1` 외에 양수 금지)
   - 키보드 ESC/Enter 처리 (모달·드롭존)

3. **리포트**

## 출력

```markdown
# /a11y pdf-merge

## Pass (12)
- 키보드 도달 OK
- 진행률 ARIA OK
- ...

## Fail (2)
- L42 아이콘 전용 버튼 (Trash2) `aria-label` 누락
- L78 진행률 영역에 `role="progressbar"` 누락

## 처방
→ a11y-auditor 가 위 2건 자동 수정
```

## 자동 수정 vs 보고

명백한 수정(누락된 `aria-label`, `role` 추가)은 자동 수정. 색·디자인 관련은 사용자 확인 후.
