PRODUCT STRATEGY · 2026.06

업로드 없는 브라우저 도구로
전 세계가 공유하는 서비스를 만든다

현존 웹 툴킷(it-tools · Squoosh · iLovePDF · TinyWow · 10015.io)의 구현방식과 성장 메커니즘을 폭넓게 수집해, 우리가 이미 보유한 169개 브라우저 완결 도구를 다시 구조화한다. 핵심 차별점은 단 하나 — "파일이 서버로 가지 않는다"는 아키텍처적 보증. 이 보증을 무기로 발견성·국제화·바이럴·수익을 동시에 끌어올리는 재설계 계획서.

현재 도구 169개 · 11 카테고리 정적 페이지 513+ 스택 Next.js 16 · React 19 · 정적 export 분석일 2026-06-05

00EXECUTIVE SUMMARY

한 문장: "무제한·무업로드·다국어 도구 허브"

경쟁사는 업로드 후 서버 처리 → 무료 제한(횟수·용량) → 유료 전환 구조다. 우리는 모든 처리가 브라우저에서 끝나므로 제한을 둘 이유가 없다. 이 구조적 우위를 제품 포지셔닝의 1순위로 끌어올리고, 발견성·SEO·국제화의 병목을 제거하는 것이 이 계획의 골자다.

01MARKET & COMPETITIVE LANDSCAPE

두 진영: "서버 처리 + 유료화" vs "브라우저 완결 + 무제한"

온라인 도구 시장은 거대하다. iLovePDF는 글로벌 #110, 인도에서만 월 229M 방문이고 트래픽의 60%가 오가닉 검색이다. 핵심은 두 가지 — 검색(SEO)이 트래픽의 본류이고, 무료 제공 폭이 진입장벽이라는 점.

서비스유형 / 스택처리 위치규모·트래픽수익 모델우리가 배울 점

핵심 통찰. 트래픽 1·2위(iLovePDF·Smallpdf)는 서버 처리라서 "용량·횟수 제한"이 불가피하다. 우리는 브라우저 완결이라 제한 자체가 없다. 즉 "무제한·무업로드"는 마케팅 카피가 아니라 물리적으로 참인 보증 — Squoosh가 증명했듯 이건 정책이 아니라 브라우저 동작 방식이 강제하는 사실이다. 이 포지션을 1순위 메시지로 전면화한다.

시장이 보내는 신호

  • 오가닉 검색이 본류다. 상위 사이트 트래픽의 60%가 검색 — 광고비가 아니라 프로그래매틱 SEO가 성장 엔진. (Zapier 5.8M·Wise 60M·TripAdvisor 226M이 이 방식으로 시장 장악)
  • AI 도구가 폭발 중. 배경제거·업스케일·얼굴처리·OCR이 가장 많이 검색됨. 우리는 이미 ONNX/TF.js로 서버 없이 보유 — 경쟁사는 GPU 서버 비용을 쓰지만 우리는 0원.
  • "무료·무가입·무워터마크"가 바이럴 트리거. 2026년 배경제거 시장조차 "무료로 충분"이 대세 — 무제한 무료는 우리의 천연 우위.

02VIRALITY · SEO · MONETIZATION MECHANICS

바이럴은 운이 아니라 구조다 — 세 개의 플라이휠
플라이휠 A

검색 플라이휠 (Programmatic SEO)

도구 1개 → 가이드 + 변환쌍(X→Y) + 비교(A vs B) + "방법" 페이지로 n배 증식. 롱테일은 경쟁 낮고 전환 2~3배. 169개 × 다국어 × 변환매트릭스 = 수만 페이지의 검색 표면.

플라이휠 B

공유 플라이휠 (Product-led)

결과물이 곧 광고. ResultCard에 "이 도구로 만듦" 워터마크 옵션·공유 링크·딥링크(설정 프리필). 만족한 사용자가 결과를 공유 → 새 사용자 유입 → 다시 공유.

플라이휠 C

신뢰 플라이휠 (Privacy)

"파일이 안 나간다"는 개발자·기업·민감문서 사용자에게 강력. 기술 블로그·HN·Reddit에서 회자될 아키텍처 서사. 오픈소스 일부 공개 시 백링크 폭발.

프로그래매틱 SEO: 페이지 증식 공식

페이지 타입템플릿 패턴타깃 검색어 예증식 규모
도구 페이지/tools/{cat}/{tool}"png to jpg", "pdf 합치기"169 × 2언어 = 338
변환 매트릭스/convert/{from}-to-{to}"heic to png", "webp to jpg"포맷쌍 수백 개
가이드("방법")/guide/{tool}"how to compress pdf without losing quality"169 × N언어
비교/compare/{a}-vs-{b}"webp vs jpeg", "mkv vs mp4"현 8 → 수십 개
유스케이스/use/{job}"이력서 사진 만들기", "단체사진 얼굴 모자이크"작업 시나리오 수십
품질 가드. 프로그래매틱 SEO의 함정은 "얇은 양산 페이지"로 인한 패널티. 각 페이지는 실제 동작하는 도구 + 고유 FAQ + 예시를 담아 "도구가 곧 콘텐츠"가 되게 한다. 빈 껍데기 페이지는 만들지 않는다.

수익화: 우리에게 맞는 하이브리드

하이브리드(광고+제휴+프리미엄)는 단일 모델보다 3~5배 성과. 단, 브라우저 완결의 신뢰를 훼손하지 않는 배치가 전제다.

① 디스플레이 광고

가이드·카탈로그·블로그에만. 도구 작업영역(드롭존~결과)엔 광고 0 — 신뢰 보호. 트래픽이 SEO로 커질수록 비례 수익.

② 제휴(Affiliate)

"더 큰 파일·자동화가 필요하면" → 데스크톱앱·클라우드 스토리지·SaaS 제휴 링크. 무업로드 한계를 자연스러운 업셀로.

③ 선택적 Pro

폴더 일괄·PWA 오프라인 팩·대용량 워커풀·배치 프리셋 저장 = 편의 기능 구독. 핵심 도구는 영원히 무료.

03CURRENT SERVICE DIAGNOSIS

자산은 일류, 구조는 성장통 직전

169개 도구·513 페이지·11 E2E 스펙·정적 export·보안헤더까지 — 토대는 탄탄하다. 문제는 "더 많은 도구·더 많은 언어·더 많은 트래픽"으로 확장할 때 드러나는 구조적 병목이다.

✓ 강점 (지킬 것)

  • 명확한 단일 미션 — "파일 무전송"이 모든 결정을 일관되게 함
  • 레지스트리 기반 자동화 — 카탈로그·사이트맵·SEO 자동 생성
  • 높은 재사용성 — FileDropZone·ResultCard·도메인 유틸(pdf/epub/ffmpeg-common)
  • 성능 토대 — 정적 export·WASM 동적 import·번들 분석 자동화
  • 테스트·SEO·다국어 골격 — 11 E2E, JSON-LD, hreflang, 가이드 자동생성

✗ 약점 (재설계 대상)

  • 발견성 낮음 — 169개를 카탈로그+기본검색으로만 탐색
  • 동기화 부채 — registry / guide-content / en-tools 3중 관리
  • 영문화 34% — 111개가 한국어 전용 → 국제 트래픽 손실
  • 페이지 일관성 부족 — 169 페이지 UI 패턴 제각각
  • 대용량·취소 처리 불균형 — AbortSignal·워커풀 표준 없음
  • 관측 한계 — CWV가 도구 단위로 분해 안 됨
  • 수익 포지션 부재 — 무업로드 우위가 제품에 미반영

확장성 한계선

현재 구조로 안전한 도구 수~250개
그 이상: 카탈로그 검색·가이드 빌드·사이트맵이 선형 악화재구조화 필요

즉 지금이 구조를 다시 짜기 가장 좋은 시점이다. 도구가 250개를 넘기 전에 모듈 규약·발견성·국제화 골격을 바꿔두면, 이후엔 도구를 "꽂기만" 하면 SEO·다국어·테스트가 자동 상속된다.

05TARGET ARCHITECTURE (재설계)

5계층 — "도구를 꽂으면 나머지가 상속된다"

현재는 페이지·레지스트리·가이드·국제화가 수평으로 흩어져 서로 동기화돼야 한다. 목표 구조는 툴 모듈을 단일 진실원으로 두고, 그 위 계층들이 모듈에서 자동 파생되게 한다.

L1 · 표현
App Router (정적 export) — 도구 페이지·가이드·변환매트릭스·비교·유스케이스. 모두 모듈 메타에서 자동 라우팅·자동 SEO. 명령 팔레트·허브·카테고리 셸.
L2 · 아키타입
5개 페이지 템플릿 — 단일 I/O · 비교(Dual) · 일괄(Folder) · 생성기 · 텍스트변환. 도구는 아키타입을 "선언"만 하면 표준 UI(드롭존·진행률·결과·취소·관련도구)를 상속.
L3 · 툴 모듈
단일 진실원 — tools/<id>/: meta · ui · logic(worker) · guide(ko/en/…) · examples · test. 레지스트리·사이트맵·i18n·가이드가 전부 여기서 파생. §06
L4 · 코어 서비스
공용 엔진 — 워커풀 · AbortSignal 표준 · WASM 자산 매니페스트(단일 버전원) · 서비스워커 캐시 티어 · 퍼지검색 인덱스 · 사용량/즐겨찾기 스토어 · CWV(도구별).
L5 · 도메인 유틸
WASM/라이브러리 래퍼 — pdf · image · ffmpeg · onnx(yunet) · tesseract · epub · crypto · zip. 동적 import + 캐시 + 진행률 콜백 (기존 자산 재사용).

핵심 전환: "수평 동기화" → "수직 파생"

07DISCOVERABILITY & UX OVERHAUL

"찾아 헤매기"에서 "바로 도달"로

169개는 인간이 카탈로그를 훑어 찾기엔 많다. 명령 팔레트·작업기반 진입·개인화로 첫 도구까지의 거리를 줄인다.

① 명령 팔레트 ⌘K (전역)

키보드 우선. 퍼지검색(Fuse.js)으로 오타·부분일치 허용. 결과를 버킷으로 — 최근 사용 · 즐겨찾기 · 도구 · 가이드 · 변환. 각 항목에 아이콘·힌트·단축키. 모바일은 큰 검색 시트.

② 작업기반 진입(Use-case)

"무엇을 하려는가"로 라우팅. /use/단체사진-얼굴-가리기 → 관련 도구 묶음 + 단계 안내. SEO 유스케이스 페이지가 곧 온보딩.

③ 개인화 홈

최근 사용 5개 · 즐겨찾기 · "당신이 자주 쓰는" 추천. localStorage 기반(서버 0). 재방문자의 첫 클릭을 1초로.

④ 워크플로 동선

결과 화면에서 "다음 단계" 제안 — 합치기→압축→서명. related 메타 기반. 체류·페이지뷰·SEO 내부링크 동시 강화.

카테고리 허브 리치화

현재 카테고리는 단순 그리드. 각 카테고리에 설명·인기 도구·자주 묻는 질문·관련 가이드를 담은 CollectionPage로 승격 → 정보형 검색 흡수 + 발견성 동시 해결.
